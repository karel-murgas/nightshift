# Memory index — {{project}}

Read this at the start of every conversation and load what it points at. Nothing else
here is loaded automatically.

**Orientation vs. detail.** The files in the first table are *orientation*: small,
current, read to get your bearings. Keep them that way. When one grows a dated
narrative, move the narrative to a companion — a state_history or arch_detail beside it —
and leave one line behind. That companion is then loaded only when a concrete question sends
you there — never "just in case", which is the single easiest way to spend a session's
context before doing any work.

## Orientation

| File | Type | What it holds |
|---|---|---|
| [arch.md](arch.md) | project | module map, one line per module; key types and events |
| [state.md](state.md) | project | current state, open items, known gaps |
| [design.md](design.md) | project | the decisions that are settled, and why |

## Rules and references

Add a row when you add a file. A `feedback_<topic>.md` records a rule the maintainer gave
you, with its reason — the reason is what stops the next session working around it.
